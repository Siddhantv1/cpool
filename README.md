# Cpool

Perficient's internal carpool app. Employees share rides between home and office with verified colleagues.
Android and iOS, built with Expo (React Native, JavaScript).

## Requirements

- Node.js LTS
- Android Studio (Android SDK + emulator), with `ANDROID_HOME` and `JAVA_HOME` set
- An Android phone with USB debugging, or the emulator

## Run

Maps use Mapbox. Copy `.env.example` to `.env` and paste your Mapbox public token (`pk.…`). `.env` is git-ignored; never commit a token.

```bash
npm install
npx expo run:android      # first time, or after adding a package with native code
npx expo start            # daily: then press "a" to open on Android
```

Expo Go is not supported; use the development build that `expo run:android` installs.

## API (shared with the backend)

All routes except auth need `Authorization: Bearer <token>`.

| Method | Path | Purpose |
|---|---|---|
| POST | `/v1/auth/signup` | `{email}` → sends code (error if the account already exists) |
| POST | `/v1/auth/forgot` | `{email}` → sends code (same answer whether or not the account exists) |
| POST | `/v1/auth/verify` | `{email, code, purpose: "signup" \| "reset"}` → `{token}` (short-lived) |
| POST | `/v1/auth/set-password` | `{token, password}` → `{ok}` (creates the account or resets the password, based on the token) |
| POST | `/v1/auth/login` | `{email, password}` → `{token}`. Errors: `not_registered` (no account for this email), `wrong_password` |
| GET / PUT | `/v1/me`, `/v1/me/vehicles`, `/v1/me/devices` | profile, vehicles, push token |
| PUT | `/v1/me` | `{role: "guest" \| "host"}` set at first-time setup. Login returns `role` (null on first sign-in) and `vehicle` |
| POST | `/v1/me/vehicles` | `{type: "bike" \| "car", number, model, mfgMonth, mfgYear, colour?, seats (bike = 1, car = 1–7), helmet: "host" \| "guest" \| null}` |
| POST | `/v1/rides` | offer a ride |
| GET | `/v1/rides/search` | find rides near a meet point |
| POST | `/v1/rides/{id}/cancel` · `start` · `complete` | ride actions |
| POST | `/v1/rides/{id}/bookings` | request a seat with a meet point |
| POST | `/v1/bookings/{id}/accept` · `reject` · `cancel` · `picked-up` · `no-show` | booking actions |
| POST / GET | `/v1/rides/{id}/locations` · `/v1/rides/{id}/live` | send location · read live position |
| POST | `/v1/rides/{id}/sos` | raise SOS |

Place search ("Where to?") calls the Mapbox Search Box API directly from the app with the public token, so the backend doesn't need a search route.

If an API shape changes, update this table first so the app and the backend stay in sync.
