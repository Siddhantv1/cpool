# Cpool

Perficient's internal carpool app. Employees share rides between home and office with verified colleagues.
Android and iOS, built with Expo (React Native, JavaScript).

## Requirements

- Node.js LTS
- Android Studio (Android SDK + emulator), with `ANDROID_HOME` and `JAVA_HOME` set
- An Android phone with USB debugging, or the emulator

## Run

Maps use Mapbox. Copy `.env.example` to `.env` and paste your Mapbox public token (`pk.…`). `.env` is git-ignored; never commit a token.

```bash
npm install
npx expo run:android      # first time, or after adding a package with native code
npx expo start            # daily: then press "a" to open on Android
```

Expo Go is not supported; use the development build that `expo run:android` installs.

## Notes

- The backend (Django) lives in `backend/` (see below). `src/lib/api.js` returns fake data until it is connected.
- `android/` and `ios/` are generated by `npx expo prebuild` and are not committed.

## Backend (Django)

Python 3.12+. From the repo root:

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate             # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser   # for the admin panel (username = your email)
python manage.py runserver         # http://localhost:8000
python manage.py test api          # run the tests
```

- **Swagger UI** (try every route in the browser): http://localhost:8000/api/docs/
- **Admin panel** (users, vehicles, codes; untick *Active* to switch someone off): http://localhost:8000/admin/
- **Sign-in codes** print in the `runserver` terminal. To send real emails, set `EMAIL_HOST`, `EMAIL_USER`, `EMAIL_PASSWORD` (and `EMAIL_FROM`).
- **From the phone over USB:** `adb reverse tcp:8000 tcp:8000`, then the app can use `http://localhost:8000`.
- **SOS emails:** set `SOS_EMAIL` to the security desk's address.
- **Production:** set `DJANGO_DEBUG=0`, `DJANGO_SECRET_KEY` and `DJANGO_ALLOWED_HOSTS`.

## API (shared with the backend)

All routes except auth need `Authorization: Bearer <token>`. Errors are HTTP 4xx with `{code, message}`; invalid input also has `fields: {name: message}`.

| Method | Path | Purpose |
|---|---|---|
| POST | `/v1/auth/signup` | `{email}` → sends code (error if the account already exists) |
| POST | `/v1/auth/forgot` | `{email}` → sends code (same answer whether or not the account exists) |
| POST | `/v1/auth/verify` | `{email, code, purpose: "signup" \| "reset"}` → `{token}` (valid 15 min). Errors: `wrong_code`, `code_expired` (10 min), `too_many_tries` (5) |
| POST | `/v1/auth/set-password` | `{token, password, phone}` → `{ok}`. A sign-up token creates the account and **needs `phone`** (Indian mobile, 10 digits starting 6–9; `+91` optional; stored as `+91XXXXXXXXXX`). A reset token resets the password (`phone` ignored) and signs out every phone. Errors: `token_expired`, `phone_required`, `invalid_phone`, `weak_password`, `already_registered` |
| POST | `/v1/auth/login` | `{email, password}` → `{token, role, vehicle}`. Errors: `not_registered` (no account for this email), `wrong_password`, `account_disabled` |
| POST | `/v1/auth/logout` | → `{ok}` (the token stops working) |
| GET / PUT / PATCH | `/v1/me` | `{email, name, gender, phone, role, vehicle}`; PUT and PATCH change only the fields sent (`name`, `gender`, `phone`, `role`). `phone`: same Indian mobile check as sign-up (can be changed, not removed) |
| GET | `/v1/me/trip` | what Home shows (poll it): `{ride, booking}`. `ride` = the ride you host (with its `bookings`, oldest first; each has `alongKm`, how far along your route that guest is, so sort by it to drive pickups in order), `booking` = your latest seat request (kept 24 h after it ends, so you see "declined") |
| GET | `/v1/me/vehicles` | your vehicles; `isDefault` marks the default (the one you picked, else the first added) |
| PATCH / DELETE | `/v1/me/vehicles/{id}` | edit (same fields as adding; only the ones sent change) · remove (kept for past rides, gone from the app). Error: `vehicle_in_use` while that vehicle is on an open ride |
| POST | `/v1/me/vehicles/{id}/default` | make it the default → your vehicle list |
| GET | `/v1/me/alerts` | Alerts tab, newest first: `[{id, kind: "request" \| "accepted" \| "declined" \| "cancelled", title, text, at, read, who: {name, initials}, rideId, bookingId}]` |
| POST | `/v1/me/alerts/read` | `{ids?}` → marks those alerts read (all of them if `ids` is left out) |
| DELETE | `/v1/me/alerts/{id}` | removes one alert (swipe away) |
| GET | `/v1/me/history` | My rides → Past and the Account numbers: `{stats: {ridesTaken, ridesGiven, kmShared}, rides: [{role: "guest" \| "host", rideId, when, from, to, with: [names], km}]}` (finished rides) |
| POST | `/v1/me/delete` | `{password}` → deletes your account: signs you out and wipes your name, email, phone and number plates (past rides stay for the other people, shown as "Deleted user"). Errors: `wrong_password`, `already_on_trip` |
| PUT | `/v1/me/devices` | push token (not built yet) |
| POST | `/v1/me/password` | `{current, new}` → `{ok, token}`. Other phones are signed out: use the new token from now on. Errors: `wrong_password`, `weak_password` |
| PUT | `/v1/me` | `{role: "guest" \| "host"}` set at first-time setup. Login returns `role` (null on first sign-in) and `vehicle` |
| POST | `/v1/me/vehicles` | `{type: "bike" \| "car", number, model, mfgMonth, mfgYear, colour?, seats (bike = 1, car = 1–7), helmet: "host" \| "guest" \| null}` |
| POST | `/v1/rides` | `{from, to, departAt, seats, vehicleId?, route: [[lng,lat],...]}`; `from`/`to` = `{officeId}` or `{name, coords}`, exactly one an office. `departAt` 10 min – 7 days ahead. Errors: `needs_office`, `bad_time`, `no_vehicle`, `too_many_seats`, `already_on_trip` |
| GET | `/v1/rides/search` | `?officeId=&direction=to_office\|from_office&at=<ISO>&lng=&lat=` (your pickup, or your drop when leaving the office) → rides leaving ±30 min whose route passes within 1.5 km: `[{id, host, departAt, meetPoint, walkToMeters, rideKm, walkFromMeters, seatsFree, seatsTotal, match: "full"\|"partial", route}]`. `route` is only the part you ride on; `host.phone` is null until accepted |
| POST | `/v1/rides/{id}/cancel` · `start` · `complete` | host only. `cancel {reason?}` cancels every booking; `complete` needs `start` first |
| POST | `/v1/rides/{id}/bookings` | `{meetPoint: [lng,lat], meetName}` → your booking. Errors: `own_ride`, `ride_closed`, `ride_full`, `already_on_trip` (one trip at a time) |
| POST | `/v1/bookings/{id}/accept` · `reject` · `cancel` · `picked-up` · `no-show` | host: `accept` (takes a seat; `ride_full` if none left), `reject`, `picked-up` / `no-show` (after `start`). Guest: `cancel {reason?}` (withdraws a request or frees a confirmed seat). Status: `requested` → `accepted` / `declined` / `withdrawn` / `cancelled` (by host) → `picked_up` / `no_show` |
| POST / GET | `/v1/rides/{id}/locations` · `/v1/rides/{id}/live` | host or confirmed guest. Send `{coords, heading?, atMeetPoint?}` every ~5 s (`atMeetPoint`: the guest's phone says it's within 50 m of the meet point). `live` → `{host: {coords, heading, at}, guests: [{bookingId, name, coords, heading, at, atMeetPoint}]}`: guests see the host only, the host sees their guests |
| POST | `/v1/rides/{id}/sos` | `{coords?}` → saved for the security desk (admin panel); also emailed if `SOS_EMAIL` is set |

Place search ("Where to?") calls the Mapbox Search Box API directly from the app with the public token, so the backend doesn't need a search route.

If an API shape changes, update this table first so the app and the backend stay in sync.
